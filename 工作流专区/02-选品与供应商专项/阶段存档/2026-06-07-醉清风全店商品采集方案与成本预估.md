# 2026-06-07 醉清风全店商品采集方案与成本预估

## 目标

为 Teddy 低端店建立 1688 上海醉清风健康科技股份有限公司的全店商品基础库，字段包括：

- 商品名称
- 商品图片
- 规格/型号
- 单价
- 优惠价/登录价
- 下单链接
- 销量
- 所属类目
- 数据状态/校验状态

## 已知基础

- 1688 店铺：上海醉清风健康科技股份有限公司
- 店铺商品规模：约 2180 件
- 已识别类目包括：每月上新、组合链接专区、外卖实体必买清单、外卖实体带图片卡纸内衣、计生专区、男用专区、女用专区、情趣专区、情趣内衣、品牌专区、谜姬电动等。
- 低端店目标：15-20 个品类，开店前 800-1000 个 SKU。

## 推荐采集流程

1. 第一层：类目目录采集
   - 用已登录浏览器读取醉清风店铺全部类目、类目 ID、类目商品数量。
   - 输出类目总表。

2. 第二层：AnySearch 基础候选采集
   - 用 AnySearch 批量搜索“醉清风 + 类目/商品关键词”。
   - 用于快速找候选详情页、外部缓存结果和可能的商品链接。
   - 不直接入正式表，只作为候选来源。

3. 第三层：1688 店铺页校验
   - 用已登录浏览器/CDP 按类目翻页采集列表页数据。
   - 核对商品必须来自醉清风店铺。
   - 采集字段：商品名、列表价/红包价、销量、商品卡图片、详情页链接。

4. 第四层：详情页补全
   - 对候选 SKU 批量进入详情页。
   - 补规格/型号、SKU 选项、主图、起批量、价格档。
   - 低价值重复款可先只保留列表层数据，避免浪费时间。

5. 第五层：表格清洗
   - 去重：同款不同链接、组合链接、赠品链接、重复规格。
   - 分类：按 Teddy 低端店品类结构重新归类。
   - 标记：可直接备货、待复核、疑似不适合平台、图片/标题需合规改写。

6. 第六层：输出文件
   - 全店原始商品库。
   - 低端店优先 SKU 池。
   - 待复核商品清单。
   - 供应商链接/类目索引表。

## 时间预估

### 快速样本测试

- 范围：1-2 个类目，约 30-80 个商品。
- 时间：1-2 小时。
- 目的：验证采集链路、图片字段、规格字段、链接稳定性。

### 全店基础表

- 范围：约 2180 件商品。
- 字段：名称、图片、列表价/优惠价、销量、下单链接、所属类目。
- 时间：8-16 小时。
- 前提：已登录浏览器能稳定读取 1688 店铺列表页。

### 全店详情增强表

- 范围：约 2180 件商品。
- 字段：增加规格型号、SKU 选项、价格档、主图校验。
- 时间：20-40 小时。
- 风险：1688 动态页面、登录态、反爬、详情页加载不稳定。

### Teddy 低端店 800-1000 SKU 可用池

- 范围：从全店商品中筛选 800-1000 个适合上架的 SKU。
- 时间：12-24 小时。
- 产物更适合实际开店，优先级高于全店 2180 件逐条精修。

## Token 预估

采用脚本本地采集、分批保存，不把全部商品详情一次性塞进对话上下文。

- 采集方案与小样测试：约 2万-4万 token。
- 全店基础表采集与多轮校验：约 8万-15万 token。
- 全店详情增强 + 低端店 SKU 筛选：约 15万-30万 token。
- 如果要求每个商品都逐条让我阅读、判断、改标题、写备注，可能超过 30万 token。

## 建议执行口径

先不要直接做 2180 件全店详情增强。推荐顺序：

1. 先做 1 个高价值类目样本测试，确认字段完整度。
2. 再做全店基础表，拿到商品池。
3. 再按 Teddy 低端店 15-20 类目结构筛出 800-1000 SKU。
4. 最后只对入选 SKU 做详情页增强和平台上架标题改写。

这样更省时间，也更符合开店目标。
