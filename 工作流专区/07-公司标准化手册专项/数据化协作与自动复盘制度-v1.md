# Teddy 数据化协作与自动复盘制度 v1

> 更新时间：2026-06-10  
> 当前状态：核心规则已确认  
> 用途：规范 Teddy 使用 Codex、数据看板、异常提醒、会议最小化、培训考核、流程可视化和责任追究的管理方式。  
> 适用范围：总部管理层、城市/区域运营层、市场中层、门店/前置仓负责人、各部门负责人，以及愿意学习使用 Codex 的基层员工。  
> 注意：涉及降薪、调岗、解除、扣回、追偿等事项，后续需要写入劳动合同、员工手册、岗位说明书、奖惩制度或配套协议，并结合当地劳动法规审核。

## 一、DWR-001 Codex 数据化协作原则

Teddy 采用“Codex 工作流 + 数据看板 + 异常提醒 + 少量关键复盘”的管理方式。

公司不以传统日报、周报、层层汇报作为主要管理方式，而以系统自动汇总、岗位数据看板、异常提醒和少量关键复盘作为主要管理方式。

管理目标是：

1. 员工少写汇报，多做实际工作。
2. 日常信息尽量在任务、订单、库存、财务、客服、招商、平台等系统中自动沉淀。
3. Codex 帮助总部和中层整理任务、数据、流程、复盘和制度。
4. 负责人看自己负责范围的数据，总部看全国汇总和重大异常。
5. 能异步解决的事项不开会，能通过系统看清楚的事项不要求人工重复汇报。

### 1.1 Codex 使用要求

| 层级 | Codex 使用要求 |
|---|---|
| 总部管理层 | 必须使用 |
| 城市/区域负责人 | 必须使用 |
| 区域经理/市场中层 | 必须使用 |
| 门店/前置仓负责人 | 建议使用，逐步培训 |
| 普通业务员 | 不强制，鼓励学习 |
| 门店执行人员 | 不强制，鼓励学习 |
| 兼职/临时人员 | 不强制 |

市场区域经理以下的业务员和门店人员，不强制要求使用 Codex。

但公司鼓励愿意学习的基层员工使用 Codex，提高个人效率、减少重复沟通、快速查找流程资料。

### 1.2 数据化协作口径

Teddy 的数据化协作制度以总部和中层管理岗位为强制使用对象，基层业务员和门店人员不强制使用 Codex。

公司通过 Codex 汇总任务、数据、流程和复盘，减少传统会议和人工汇报，让总部看全国，中层看区域，门店看执行。

## 二、DWR-002 数据层级与看板权限

Teddy 数据看板按总部全国、城市/区域、门店/前置仓、岗位/部门四层设置。

上级主要看汇总和异常，本级看执行细节，敏感数据按岗位授权，尽量通过 Codex 和系统自动汇总减少人工汇报。

### 2.1 总部全国看板

总部看全国结果和重大风险，不追每个基层小动作。

总部看：

1. 全国营业额、订单数、客单价、净利润。
2. 各城市业绩排名。
3. 各城市门店数量、开店进度、存活率。
4. 各品牌店数据：TEDDY TOGO、TEDDY BELLE、RAINBOW TEDDY。
5. 全国库存周转、缺货、滞销、爆品。
6. 全国平台风险：审核失败、违规、下架、处罚。
7. 全国招商数据：线索、签约、开店、回款、存活。
8. 全国财务数据：收入、成本、费用、现金流。
9. 全国重大客诉和品牌风险。
10. 各部门异常事项。

### 2.2 城市/区域看板

城市/区域负责人看本区域经营，不看全国所有细节。

城市/区域看：

1. 本城市营业额、订单数、客单价、净利润。
2. 本城市各门店业绩。
3. 本城市门店开店进度和异常。
4. 本城市库存、缺货、滞销、补货。
5. 本城市平台审核、违规、活动效果。
6. 本城市客服、差评、退款、投诉。
7. 本城市招商线索、签约、开店、回款。
8. 本城市人员排班、任务完成、卡点。
9. 本城市加盟商赋能记录。
10. 本城市需要总部审批的事项。

### 2.3 门店/前置仓看板

门店负责人看自己门店的执行数据。

门店看：

1. 当日订单、营业额、客单价。
2. 接单、打包、配送异常。
3. 库存、缺货、效期、盘点差异。
4. 客服、退款、差评、投诉。
5. 上架进度、商品异常、价格异常。
6. 包装物料和设备状态。
7. 当日任务、卡点、待协助事项。
8. 加盟商或门店负责人评分和反馈。
9. 门店净利润和成本结构。
10. 门店整改事项。

### 2.4 岗位/部门看板

各岗位只看自己负责的业务数据，避免信息过载。

示例：

1. 财务与数据岗看收入、费用、利润、现金流。
2. 商品与供应链岗看供应商、采购、补货、爆品滞销。
3. 平台运营岗看上架、审核、活动、违规、评分。
4. 客服与售后岗看咨询、退款、差评、投诉。
5. 市场招商岗看线索、签约、回款、开店、门店存活。
6. 标准化与培训岗看 SOP 执行、培训记录、门店问题。

### 2.5 权限原则

1. 本级看本级经营数据。
2. 上级看下级汇总和异常，不默认看所有细节。
3. 总部看全国汇总、趋势、风险和重大事项。
4. 财务、合同、薪酬、客户资料等敏感数据按岗位授权。
5. 系统自动汇总优先，人工汇报只补充异常原因。

## 三、DWR-003 异常提醒机制

Teddy 的数据化管理采用：

> 数据自动汇总 + 异常自动提醒 + 本级先处理 + 超权限再升级。

### 3.1 异常分级

| 等级 | 含义 | 处理方式 |
|---|---|---|
| 红色异常 | 会影响资金、品牌、平台、合同、合规、重大客户关系 | 立即升级上一级，必要时总部处理 |
| 黄色异常 | 会影响门店经营、订单、库存、客服、招商进度 | 本级负责人当天处理，抄送上级 |
| 蓝色异常 | 轻微偏差或待观察问题 | 进入任务看板，持续跟踪 |

### 3.2 必须提醒的异常类型

1. 经营异常：营业额连续下滑、订单数异常、客单价异常、毛利低于标准、门店亏损、推广费异常。
2. 库存异常：爆品缺货、滞销积压、效期临近、库存账实不符、补货超预算。
3. 平台异常：商品审核失败、商品下架、店铺评分下降、平台处罚、活动效果异常。
4. 客服异常：差评、退款率上升、重大客诉、隐私包装投诉、错发漏发。
5. 财务异常：支出超预算、回款未到账、票据缺失、现金流低于安全线。
6. 招商异常：线索质量低、签约转化差、客户退款、市场人员乱承诺、加盟商投诉。
7. 人员异常：关键岗位任务长期延期、无人负责、交接不清、门店人员频繁失误。
8. 合规异常：证照、平台规则、商品图文、宣传话术、合同、收款出现风险。

### 3.3 提醒原则

1. 本级能处理的，本级处理。
2. 本级处理不了的，升级上一级。
3. 上一级处理时，抄送再上一级。
4. 总部只看红色异常、趋势异常和跨区域共性问题。
5. 蓝色异常不打扰总部，只进入任务看板。
6. 同一问题连续出现 3 次，必须进入复盘。

### 3.4 Codex 的作用

Codex 负责帮助总部和中层：

1. 汇总各部门数据。
2. 识别异常趋势。
3. 生成异常清单。
4. 提醒责任岗位。
5. 输出复盘建议。
6. 把解决方案沉淀为 SOP。

## 四、DWR-004 会议最小化机制

Teddy 原则上不鼓励频繁开会。

能通过系统、Codex、任务看板、数据看板、异步留言解决的问题，不开会。

### 4.1 不需要开会的情况

1. 任务状态已经清楚。
2. 数据看板已经能说明问题。
3. 责任岗位和截止时间已经明确。
4. 只是同步进度，没有决策事项。
5. 只是提醒对方完成任务。
6. 可以通过 Codex 汇总或生成报告解决。

### 4.2 必须开会的情况

只有以下情况才需要开会：

1. 重大决策：战略、资金、品牌、合同、供应商、招商政策等。
2. 跨部门冲突：多个岗位意见不一致，异步无法解决。
3. 红色异常：资金、平台、合规、品牌、重大客户关系风险。
4. 连续异常：同一问题连续出现 3 次。
5. 周期复盘：需要看数据、定改进动作。
6. 新制度发布：需要确认理解和执行标准。
7. 重大人员事项：任命、变更、薪酬、分红、退出。

### 4.3 会议规则

每个会议必须满足 5 个条件：

1. 有明确议题。
2. 有必须参会岗位。
3. 有决策事项或待解决问题。
4. 有开始和结束时间。
5. 会后有结论、责任岗位、截止时间。

没有结论、责任岗位、截止时间的会议，不算有效会议。

### 4.4 会议时长建议

| 会议类型 | 建议时长 |
|---|---:|
| 日常短同步 | 5-10 分钟，能异步则不开 |
| 异常处理会 | 15-30 分钟 |
| 周复盘会 | 30-60 分钟 |
| 月度经营会 | 60-90 分钟 |
| 重大决策会 | 按事项复杂度确定，但必须提前发资料 |

### 4.5 会议输出

会议结束后必须输出：

1. 决策结论。
2. 责任岗位。
3. 协同岗位。
4. 截止时间。
5. 验收标准。
6. 是否需要同步其它工作流或制度。

## 五、DWR-005 培训考核与异常责任追究机制

Teddy 鼓励员工学习、改正和成长，不把普通失误都变成扣钱处罚。

但对低级错误、明知故犯、屡次犯错、造成公司损失或影响同事利益的行为，必须严肃处理。

所有岗位上岗前必须经过培训和考核，关键岗位实行“考核合格后独立上岗”。

### 5.1 基础原则

1. 先培训再上岗。
2. 普通错误重学习。
3. 低级错误要停岗复训。
4. 重复错误要进入惩戒。
5. 红色问题直接严肃处理。
6. 责任认定要看原因。
7. 处罚必须有证据。

### 5.2 分级处理建议

| 异常等级 | 典型情况 | 处理方式 |
|---|---|---|
| 蓝色问题 | 轻微偏差、技能不熟、流程理解不到位 | 增加学习、辅导、复训，不直接处罚 |
| 黄色问题首次 | 已影响工作结果，但未造成重大损失 | 暂停独立操作、重新培训、重新考核，通过后恢复 |
| 黄色问题重复 | 同类问题反复出现，说明能力或态度有问题 | 书面警示、扣减绩效/奖金资格、调整岗位权限 |
| 红色问题 | 造成资金、平台、品牌、客户、合同、合规重大风险 | 立即暂停相关权限，启动调查；可调岗、降级、取消奖金，严重时解除合作/劳动关系 |
| 明知故犯/虚假/飞单/私收款 | 主观违规或损害公司利益 | 重罚，扣回奖金提成，终止分红，必要时解除并追责 |

## 六、DWR-006 持证上岗与岗位考核机制

这里的“持证”不是国家证书，而是公司内部的岗位上岗资格。

关键岗位必须培训合格后再独立操作。

### 6.1 必须持内部上岗资格的岗位

这些岗位没通过培训考核，不能独立上岗：

1. 门店/前置仓负责人岗。
2. 平台运营岗。
3. 商品上架岗。
4. 库存管理岗。
5. 客服与售后岗。
6. 履约打包岗。
7. 财务与数据岗。
8. 合规与资质岗。
9. 招商加盟市场岗。
10. 加盟商运营支持岗。
11. 标准化与培训岗。

### 6.2 上岗前必须培训的内容

1. 公司战略和品牌定位。
2. 岗位职责和权限边界。
3. 标准 SOP。
4. 系统和 Codex 使用方式。
5. 数据填写规则。
6. 客户隐私和服务标准。
7. 平台规则和合规红线。
8. 财务、收款、票据、费用规则。
9. 错误分级和责任追究机制。
10. 岗位实操演练。

### 6.3 考核方式

1. 理论考试：看是否理解制度和流程。
2. 实操考核：看是否能按 SOP 独立完成。
3. 情景模拟：看遇到异常会不会处理。
4. 带教观察：新员工前期由老员工或上级岗位带教。
5. 试岗评估：试岗期内看真实执行结果。

### 6.4 上岗资格等级

| 等级 | 含义 | 权限 |
|---|---|---|
| L0 学习中 | 已入职但未通过考核 | 只能学习和旁听，不能独立操作 |
| L1 辅助上岗 | 通过基础考核 | 可在指导下操作 |
| L2 独立上岗 | 通过实操考核 | 可独立完成岗位任务 |
| L3 带教上岗 | 表现稳定且通过带教资格 | 可培训新人 |
| L4 主管/负责人 | 具备管理和复盘能力 | 可管理岗位或门店团队 |

### 6.5 复训触发条件

以下情况必须复训：

1. 黄色问题首次发生。
2. 同类蓝色问题连续出现 3 次。
3. SOP 更新。
4. 平台规则或合规规则变化。
5. 岗位长期未操作后重新上岗。
6. 转岗或晋升。
7. 门店开业前集中培训。
8. 红色问题调查后仍允许留岗的。

## 七、DWR-007 岗位职责与流程可视化制度

Teddy 所有岗位和跨部门协作流程，必须做到：

> 岗位有说明书，任务有流程图，协作有责任边界，异常有升级路径，资料能在共享文档中快速找到。

### 7.1 基础要求

1. 每个岗位必须有岗位说明书。
2. 每个核心工作必须有流程图。
3. 每个跨部门协作必须有协作流程图。
4. 流程图必须标清谁发起、谁负责、谁协同、谁审批、谁抄送、卡点升级给谁。
5. 每个流程必须有输入、输出和异常分支。
6. 所有流程图进入共享文档库。
7. 培训和考核必须基于流程图。
8. 处罚必须基于已发布流程和已完成培训考核。

### 7.2 处罚前提

如果流程没写清、培训没做到位，优先优化制度和培训。

如果流程清楚、培训考核通过后还犯低级错误，才进入责任追究。

### 7.3 共享文档结构建议

1. 岗位说明书库。
2. 流程图库。
3. 跨部门协作流程。
4. 异常处理流程。
5. 培训考核资料。
6. 岗位任命表。
7. 制度版本记录。

## 八、DWR-008 蓝黄红问题分级与处罚表

惩罚不是为了让人害怕犯错，而是为了让低级错误、重复错误、主观违规和损害公司利益的行为付出代价。

### 8.1 蓝色问题：学习提升类

典型情况：

1. 新人技能不熟。
2. 流程理解有偏差。
3. 数据填写轻微遗漏。
4. 未造成明显损失。
5. 未影响客户体验或平台结果。

处理方式：

1. 指导纠正。
2. 增加学习。
3. 补充流程说明。
4. 记录一次蓝色问题。
5. 同类蓝色问题连续 3 次，升级为黄色问题。

### 8.2 黄色问题：暂停独立操作 + 复训考核类

典型情况：

1. 因个人疏忽导致任务延期。
2. 上架信息错误。
3. 库存记录错误。
4. 打包错漏但未造成重大损失。
5. 客服回复不规范引发客户不满。
6. 未按流程操作但及时纠正。
7. 同类蓝色问题连续 3 次。

处理方式：

1. 第一次黄色问题：暂停该项独立操作。
2. 重新培训。
3. 重新考核。
4. 通过后恢复权限。
5. 记录到岗位能力档案。
6. 若造成损失，按制度评估责任。

### 8.3 重复黄色问题：绩效/权限处理类

典型情况：

1. 同类黄色问题重复出现。
2. 已培训考核后仍犯低级错误。
3. 影响同事工作。
4. 导致客户投诉或平台风险。
5. 多次延期影响关键节点。

处理方式：

1. 书面警示。
2. 扣减当月绩效或奖金资格。
3. 降低岗位权限。
4. 调整岗位。
5. 进入重点观察期。
6. 必要时取消晋升、带教、分红或提成资格。

### 8.4 红色问题：重大责任类

典型情况：

1. 私收款、飞单、虚假承诺。
2. 重大平台违规。
3. 泄露客户隐私。
4. 造成严重客诉或品牌伤害。
5. 造成重大财务损失。
6. 明知流程仍故意违反。
7. 篡改数据、隐瞒问题。
8. 造成合同、资质、法律风险。

处理方式：

1. 立即暂停相关权限。
2. 启动事实调查。
3. 调岗、降级、取消绩效奖金、提成或分红资格。
4. 造成损失的依法追责。
5. 严重者解除劳动关系或合作关系。
6. 必要时移交司法或平台处理。

## 九、DWR-009 责任认定流程

Teddy 所有处罚必须先做事实收集、问题分级、原因判断和责任归属。

没有证据不处罚，没有培训不重罚，没有流程不甩锅；但流程清楚、培训通过后仍犯低级错误或主观违规的，必须严肃处理。

### 9.1 责任认定七步流程

1. 异常发现：由系统、Codex、上级岗位、门店负责人、客户投诉、平台通知或数据异常发现问题。
2. 事实收集：收集任务记录、聊天记录、系统数据、平台截图、客户反馈、监控记录、付款记录、库存记录等证据。
3. 问题分级：按蓝色、黄色、红色标准初步分级。
4. 原因判断：判断问题属于制度没写清、流程图缺失、培训不到位、系统工具问题、协同岗位未配合、个人技能不足、个人疏忽、主观违规或恶意损害公司利益。
5. 责任归属：判断是个人责任、岗位责任、协同责任、管理责任、制度责任还是系统责任。
6. 处理决定：根据责任归属和问题等级，决定学习、复训、暂停权限、扣绩效、调岗、降级、取消分红、追偿或解除。
7. 复盘改进：每一次黄色和红色问题都必须复盘。

### 9.2 责任判断原则

1. 没有流程图、没有培训、没有考核的，优先看制度和管理责任。
2. 流程清楚、培训完成、考核通过后仍犯低级错误的，优先看个人责任。
3. 多岗位协作出错，必须看每个岗位是否按时交付。
4. 上级长期知道问题但不处理，也承担管理责任。
5. 故意隐瞒、篡改、飞单、私收款、虚假承诺，直接按严重责任处理。

### 9.3 处理要求

1. 蓝色问题可以由直属上级处理。
2. 黄色问题需要上一级复核。
3. 红色问题必须进入总部复核。
4. 涉及调岗、降薪、解除、追偿的，必须保留书面记录并进入法务/合同审核。

## 十、DWR-010 分层处罚与一线简化原则

Teddy 的红黄蓝异常机制按层级适用。

总部、大区、城市管理岗位严格按红黄蓝管理风险；一线门店岗位以简化流程、高效处理、客户满意为优先。

只要不触碰公司核心红线、不损害客户体验、不造成重大损失，一线允许在授权范围内先处理、后记录、再复盘。

### 10.1 分层管理方式

| 层级 | 管理方式 | 处罚重点 |
|---|---|---|
| 总部管理层 | 严格红黄蓝机制 | 战略、资金、品牌、合规、合同、制度错误要重罚 |
| 大区/城市管理层 | 严格红黄蓝 + 区域复盘 | 区域风险、门店督导失职、数据异常、人员管理问题 |
| 门店负责人 | 简化红黄蓝 + 结果负责 | 客户满意、履约效率、库存准确、团队执行 |
| 一线门店人员 | 红线管理 + 复训纠错 | 不用复杂流程，重点防低级错、重复错、客户投诉 |

### 10.2 一线可以简化处理的情况

1. 骑手等待，需要快速打包。
2. 客户临时改需求，需要在规则内快速处理。
3. 库存临时缺货，需要按替代方案沟通。
4. 平台订单超时风险，需要先保障履约。
5. 门店现场小问题，可以先解决后补记录。

### 10.3 一线不能跳流程的情况

1. 涉及收款、退款、私收款。
2. 涉及客户隐私泄露。
3. 涉及平台处罚、商品下架、资质风险。
4. 涉及品牌对外承诺。
5. 涉及合同、加盟商、供应商核心条款。
6. 涉及重大客诉、差评扩散、舆情风险。
7. 涉及超权限采购、调价、换货承诺。
8. 涉及虚假记录、隐瞒问题、篡改数据。

### 10.4 分层处罚原则

1. 岗位层级越高、权限越大、影响范围越广，犯错责任越重。
2. 一线普通错误优先复训和纠正。
3. 管理层制度错误、决策错误、监督失职、明知不改，必须严肃处理。
4. 一线蓝色问题以学习提升为主。
5. 一线黄色问题以暂停独立操作和复训为主。
6. 一线红线问题、重复低级错误、明显影响客户满意的问题才重罚。
